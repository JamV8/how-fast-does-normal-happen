Does the rule of 30 hold outside the textbook? (extension beyond the assignment)

Show the setup code 
source("../R/clt_functions.R")

# Treat a real dataset as the population: each observation in a sample is
# drawn at random (with replacement) from the dataset.
from_data <- function(x) function(n) sample(x, n, replace = TRUE)
pop_sd    <- function(x) sqrt(mean((x - mean(x))^2))   # SD of the whole population (divide by N)

Textbook distributions are useful because their properties are known exactly. But the reason anyone cares about the Central Limit Theorem is real data: prices, waiting times, delays, populations. This page applies the same method and the same “normal enough” standard to real datasets.

How it works. Each dataset is treated as a complete population. A “sample of size n” means picking n records at random from it, each pick independent of the others (with replacement). Then everything is the same as before: 100,000 samples per n, the four checks, and the smallest n that passes.

Even at n = 30 the means are still clearly skewed (skewness 0.59). The formula skewness/√n predicts 0.58, and the simulation agrees. This was my first sign that n = 30 is not a universal answer.

Caveats I noted. (1) This dataset contains only the longest rivers, so it says nothing about rivers in general: a bigger sample cannot fix a biased population. (2) Sampling without replacement from only 141 rivers would behave differently. At n = 141 every sample would be the whole dataset and the mean would never vary. That is why the main study samples from theoretical distributions, where every draw is independent.

An election poll: where the CLT is used every day

A poll asks n = 1,000 people a yes/no question. Suppose the true support is 52%. Each answer is a 0 or 1, which is about as far from a bell curve as possible, yet the CLT says the poll result is approximately normal.

Show code 
p <- 0.52; n_poll <- 1000
set.seed(student_id)
polls <- simulate_means(function(k) rbinom(k, 1, p), n_poll)
se_p  <- sqrt(p * (1 - p) / n_poll)
inside <- mean(abs(polls - p) <= 1.96 * se_p)
style_par(mar = c(4, 4, 1, 1))
hist(100 * polls, breaks = seq(floor(100 * min(polls)) - 0.05, ceiling(100 * max(polls)) + 0.05, by = 0.1),
     freq = FALSE, col = adjustcolor(pal$bars, 0.75), border = NA,
     xlab = "Poll result (% saying yes)", ylab = "Density", main = "")
rect(100 * (p - 1.96 * se_p), 0, 100 * (p + 1.96 * se_p), 1, col = adjustcolor(pal$zone, 0.12), border = NA)
curve(dnorm(x, 100 * p, 100 * se_p), add = TRUE, col = pal$curve, lwd = 2.2, n = 400)

A pollster runs one poll and reports “52% ± 3.10 points”. That margin comes from the CLT formula, 1.96·√(p(1−p)/n), not from repeating the poll. The simulation checks the promise: 94.7% of the simulated polls landed inside the margin, close to the promised 95%. In real life B = 1 (one poll); in a simulation we can afford B = 100,000 and see whether the formula is honest.

What the real data show

  • The rule of 30 fails for most real-world data. It works for the geyser, whose distribution is bimodal but nearly symmetric. It does not work for prices, delays, or populations, which are the kind of data analysts handle every day. These need roughly 51, 235 and 2,450 observations.
  • The skewness formula predicts the threshold well, even for messy real data: the simulated n lands near (skewness/0.25)² for the continuous datasets. One number about the population, its skewness, tells you most of what you need to know.
  • Discrete counts behave like the binomial. The inventions data pass the skewness check early but need extra observations because of the steps between possible values. This is the same pattern as in the binomial analysis.
  • Heavy tails make the CLT slow. County populations have finite variance, so the CLT does eventually apply, but only after thousands of observations. In practice that is not far from the Cauchy case. With a few giants in the data, the mean of a typical sample is dominated by whether a giant was included.

Part C. Why it matters: do real “95%” intervals catch the truth?

Everything above judged the shape of the sample means using the true population SD. A real analyst does not know the true SD. They estimate it from the same sample and report the textbook interval x̄ ± t·s/√n. For lopsided data this goes wrong in a specific way: a small sample usually misses the rare huge values, so it underestimates both the mean and the spread, and the interval comes out too low and too narrow.

So I asked the practical question directly. For each dataset I drew 100,000 samples, built the usual 95% t-interval from each, and counted how often the interval contained the true mean.

Show code: coverage of the usual 95% t-interval 
coverage <- function(x, n, reps = B, seed = student_id) {
  mu <- mean(x)
  set.seed(seed)
  res <- replicate(reps, {
    s <- sample(x, n, replace = TRUE)
    half <- qt(0.975, n - 1) * sd(s) / sqrt(n)
    c(abs(mean(s) - mu) <= half,          # interval contains the true mean
      mean(s) + half < mu)                # whole interval below the truth
  })
  c(covers = mean(res[1, ]), too_low = mean(res[2, ]), too_high = 1 - mean(res[1, ]) - mean(res[2, ]))
}

ci_rows <- do.call(rbind, lapply(real, function(z) {
  sizes <- unique(c(30, 100, z$n_main))
  do.call(rbind, lapply(sizes, function(n) {
    cv <- coverage(z$d$x, n)
    data.frame(key = z$d$key, dataset = z$d$short, n = n, covers = cv[["covers"]],
               too_low = cv[["too_low"]], too_high = cv[["too_high"]])
  }))
}))

What this means in practice. An analyst who estimates the average flight delay from 30 flights gets a “95%” interval that misses the true average 10.2% of the time instead of 5%. Almost all of those misses are on the same side: in 9.8% of studies the whole interval sits below the truth, four times the promised 2.5%, so the analyst reports delays as shorter than they really are. For county populations it is worse: the interval catches the truth only 71.7% of the time. With 235 flights per study, the number my shape tests required, coverage rises to 94.1%.

This is the practical cost of trusting the rule of 30 with lopsided data: confidence intervals and tests that look standard but quietly overstate how sure we are.

Limits of this extension

  • The dataset is treated as the whole population. Real conclusions would also depend on how the data were collected.
  • Independence is assumed. Real flight delays on the same day are correlated (one storm delays many flights), which would slow convergence further. The extra-credit dependent-process study is the place to examine this.
  • Resampling with replacement keeps the draws independent and identically distributed, matching the CLT’s assumptions.

### What the real data show

- **The rule of 30 fails for most real-world data.** It works for the geyser, whose distribution is
  bimodal but nearly symmetric. It does not work for prices, delays, or populations, which are the kind of
  data analysts handle every day. These need roughly
  `r num(real[[3]]$n_main)`, `r num(real[[4]]$n_main)` and `r num(real[[5]]$n_main)` observations.
- **The skewness formula predicts the threshold well**, even for messy real data: the simulated n lands
  near (skewness/0.25)² for the continuous datasets. One number about the population, its skewness, tells
  you most of what you need to know.
- **Discrete counts behave like the binomial.** The inventions data pass the skewness check early but need
  extra observations because of the steps between possible values. This is the same pattern as in the
  [binomial analysis](04_binomial.qmd).
- **Heavy tails make the CLT slow.** County populations have finite variance, so the CLT does eventually
  apply, but only after thousands of observations. In practice that is not far from the
  [Cauchy](05_cauchy.qmd) case. With a few giants in the data, the mean of a typical sample is dominated by
  whether a giant was included.

## Part C. Why it matters: do real "95%" intervals catch the truth?

Everything above judged the *shape* of the sample means using the true population SD. A real analyst does
not know the true SD. They estimate it from the same sample and report the textbook interval
x̄ ± t·s/√n. For lopsided data this goes wrong in a specific way: a small sample usually misses the rare
huge values, so it underestimates both the mean and the spread, and the interval comes out too low and
too narrow.

So I asked the practical question directly. For each dataset I drew 100,000 samples, built the usual 95%
t-interval from each, and counted how often the interval contained the true mean.

```{r}
#| label: ci-coverage
#| code-summary: "Show code: coverage of the usual 95% t-interval"
coverage <- function(x, n, reps = B, seed = student_id) {
  mu <- mean(x)
  set.seed(seed)
  res <- replicate(reps, {
    s <- sample(x, n, replace = TRUE)
    half <- qt(0.975, n - 1) * sd(s) / sqrt(n)
    c(abs(mean(s) - mu) <= half,          # interval contains the true mean
      mean(s) + half < mu)                # whole interval below the truth
  })
  c(covers = mean(res[1, ]), too_low = mean(res[2, ]), too_high = 1 - mean(res[1, ]) - mean(res[2, ]))
}

ci_rows <- do.call(rbind, lapply(real, function(z) {
  sizes <- unique(c(30, 100, z$n_main))
  do.call(rbind, lapply(sizes, function(n) {
    cv <- coverage(z$d$x, n)
    data.frame(key = z$d$key, dataset = z$d$short, n = n, covers = cv[["covers"]],
               too_low = cv[["too_low"]], too_high = cv[["too_high"]])
  }))
}))
write.csv(ci_rows, "../results/ci_coverage.csv", row.names = FALSE)

# 100 example intervals for flight delays at n = 30 (used by the website)
set.seed(student_id)
fl <- datasets[[4]]$x
ex <- t(replicate(100, { s <- sample(fl, 30, replace = TRUE); h <- qt(0.975, 29) * sd(s) / sqrt(30); c(mean(s) - h, mean(s) + h) }))
write.csv(data.frame(lo = ex[, 1], hi = ex[, 2]), "../results/ci_flights_examples.csv", row.names = FALSE)

  align = "lrrrr", caption = "A correct 95% interval catches the truth 95% of the time and misses 2.5% on each side.")
```

**What this means in practice.** An analyst who estimates the average flight delay from 30 flights gets a
"95%" interval that misses the true average `r pct(1 - f30$covers)` of the time instead of 5%. Almost all of those
misses are on the same side: in `r pct(f30$too_low)` of studies the whole interval sits *below* the truth,
four times the promised 2.5%, so the analyst reports delays as shorter than they really are. For county
populations it is worse: the interval catches the truth only `r pct(c30$covers)` of the time. With
`r real[[4]]$n_main` flights per study, the number my shape tests required, coverage rises to
`r pct(fmain$covers)`.

This is the practical cost of trusting the rule of 30 with lopsided data: confidence intervals and
tests that look standard but quietly overstate how sure we are.

### Limits of this extension

- **The dataset is treated as the whole population.** Real conclusions would also depend on how the data
  were collected.
- **Independence is assumed.** Real flight delays on the same day are correlated (one storm delays many
  flights), which would slow convergence further. The extra-credit dependent-process study is the place
  to examine this.
- **Resampling with replacement** keeps the draws independent and identically distributed, matching the
  CLT's assumptions.
