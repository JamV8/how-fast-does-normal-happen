A strongly right-skewed population: think waiting times

Show the simulation code 
source("../R/clt_functions.R")

rgen  <- function(n) rexp(n, rate = 1)   # one sample of size n
mu    <- 1                               # population mean
sigma <- 1                               # population SD
pop_skew <- 2                            # population skewness
pop_kurt <- 6                            # population excess kurtosis

# Stage 1: a coarse grid of sample sizes. Stage 2 (automatic): every n
# between the last coarse n that failed and the first one that passed.
coarse <- c(1, 2, 5, 10, 15, 20, 30, 45, 60, 80, 100, 150, 200,
            300, 400, 450, 500, 600, 750, 1000)
exper <- run_with_refinement(rgen, coarse, mu, sigma)

res    <- exper$results
n_main <- smallest_normal_n(res)
n_std  <- n_by_standard(res)
at     <- function(k) res[res$n == k, ]
n_first <- min(res$n[res$normal_enough])   # first n that passes at all

save_results(res, "exponential")
save_summary(res, "Exponential(1)", n_main, prediction = "45",
             key_note = "Skewness is the bottleneck; theory predicts (2/0.25)^2 = 64")

n = 71 under my main standard (strict standard: ≈ 600 · lenient standard: ≈ 20 · my prediction: 45)

1. What population am I sampling from?

The exponential distribution describes waiting times: the time until the next customer arrives, the next call comes in, or a machine fails. Most waits are short, but occasionally a wait is very long, which gives the distribution a long right tail.

Property Value
Mean μ 1
Standard deviation σ 1
Skewness 2 (strong right skew)
Excess kurtosis 6 (heavy right tail)
Theoretical SE of the mean σ/√n = 1/√n

2. What did I expect before running the simulation?

I based my prediction on a pilot run at n = 1, 15 and 20. The skewness of the sample means dropped from 0.52 at n = 15 to 0.45 at n = 20, and I extrapolated that it would reach my 0.25 limit around n = 45. From the river-length example (see Real data) I already expected that n = 30 would not be enough for a strongly skewed population.

3. Which sample sizes did I investigate?

I used the same two-stage search for every population:

  1. Coarse grid: n = 1, 2, 5, 10, 15, 20, 30, 45, 60, 80, 100, 150, 200, 300, 400, 450, 500, 600, 750, 1000, wide enough to cover both the main and the strict standard.
  2. Refinement: every n from 61 to 79, the gap between the last coarse n that failed and the first one that passed.

For every n I simulated B = 100,000 sample means with seed 9426. B only controls how precisely each sample size is measured; it is not the sample size.

5. When did the sampling distribution become approximately normal?

\[\boxed{n = 71}\]

6. Why did I choose that value?

  • At n = 71 all four checks pass: skewness 0.243, excess kurtosis 0.104, Q-Q correlation 0.9984, and tails of 1.83% / 3.13%. Every larger n I tested also passes.
  • n = 69 already passes, but n = 70 fails again, so I do not stop there. Near the threshold the skewness is sitting right at 0.25, and at B = 100,000 it is only measured to about ±0.008. My rule of taking the first n after which every tested n passes keeps one lucky simulation from deciding the answer.
  • Theory agrees: the skewness of the mean is 2/√n, which equals 0.25 at n = (2/0.25)² = 64.
  • n = 30 is not enough. At n = 30 the skewness is still 0.36, and a “95%” interval misses 3.4% of the time on the high side but only 1.4% on the low side.

7. What surprised me?

My prediction of 45 was too low; the final answer was 71. At n = 45 the histogram already looked normal to me, but the numbers did not agree. The skewness was still 0.30, and only 1.6% of the means fell below the lower 1.96 SE limit instead of 2.5%. I saw the same pattern with the river lengths at n = 30: the histogram looked fine, but the Q-Q plot still curved. I learned not to rely on the histogram alone.

The assignment asks to rerun one analysis with a different seed. I reran the full two-stage search with seed 2026 instead of 9426.

  `Lenient n` = c(n_std[["lenient"]], n_by_standard(res2)[["lenient"]]),
  `Skewness at n = 30` = f3(c(at(30)$skewness, res2$skewness[res2$n == 30])),

knitr::kable(cmp, align = "r")
Seed Chosen n (main) Strict n Lenient n Skewness at n = 30 Skewness at n = 100
9426 71 600 20 0.360 0.198
2026 69 600 20 0.378 0.189

Did the exact results change? Yes. Every number in the table moved slightly, because a different seed produces different random samples.

Did my scientific conclusion change? No. Both seeds put the threshold in the same narrow range around the theoretical value of 64, both show that n = 30 is not enough, and both show skewness as the bottleneck. With B = 100,000 the Monte Carlo noise is small compared with the effects I am measuring. A seed makes a result reproducible (anyone can get exactly my numbers); a large B makes it reliable (the conclusion does not depend on the seed).

## 6. Why did I choose that value?

- At **n = `r n_main`** all four checks pass: skewness `r f3(at(n_main)$skewness)`,
  excess kurtosis `r f3(at(n_main)$ex_kurtosis)`, Q-Q correlation `r f4(at(n_main)$qq_cor)`,
  and tails of `r pct(at(n_main)$lower_tail, 2)` / `r pct(at(n_main)$upper_tail, 2)`.
  **Every larger n I tested also passes.**
- `r flip_text(res, n_main)` Near the threshold the skewness is sitting right at 0.25, and at B = 100,000 it is only measured to about ±0.008. My rule of taking the first n after which *every* tested n passes keeps one lucky simulation from deciding the answer.

- **n = 30 is not enough.** At n = 30 the skewness is still `r f2(at(30)$skewness)`, and a "95%"
  interval misses `r pct(at(30)$upper_tail)` of the time on the high side but only
  `r pct(at(30)$lower_tail)` on the low side.
